# VP-CorrosionNet — Virtual Polarimetric Corrosion Imaging (research scaffold)

**Question.** To what extent can the corrosion-discriminative information produced by *physical* polarization imaging be transferred
into a physics-constrained, software-defined *virtual* polarimetric camera that runs on ordinary RGB images of copper/bronze cartridges?

**Status of this repository (read this first).**

| Area | State |
|---|---|
| Optics (Fresnel dielectric/conductor, Stokes, Jones→Mueller, GGX microfacet, polarized reflection, virtual analyzer, PSRF, angle search) | implemented, unit-tested against closed forms |
| Latent optical field + differentiable physics layer, CPE ensemble, VP-CorrosionNet (early/mid/late fusion; RGB/CIELAB/HSV options), teacher/student, baselines | implemented, runs on CPU |
| Synthetic renderer + validation harness | implemented (**synthetic only**) |
| Metrics, statistics, group-level splits, benchmark, robustness, ablation, hardware-gap runners | implemented |
| Figures 1–15 | Fig 1,3,4,5,6,9 (+ Fig 2 fallback) render from physics/synthetic data; 7,8,10–15 render only when real result files exist |
| **Real cartridge data, real polarization measurements, trained-model results, DeepLabV3+/YOLO baselines, Crossref-verified DOIs** | **NOT present.** No claim in this repo is an experimental result about real cartridges. |

Nothing here has been evaluated on real copper/bronze cartridges. The only measured results are the SYNTHETIC physics-validation checks in
`docs/SYNTHETIC_VALIDATION_REPORT.csv` (identities exact to float precision; untrained physics-only AoLP poor because of diffuse/specular
attribution — see `docs/LIMITATIONS.md` §2). Tables are header-only templates. Where a number appears in the
docs it comes from a script in this repo (and is labelled SYNTHETIC) or from the cited literature.

## Scientific stance (non-negotiable)
* A single RGB image does **not** determine the polarization state. Virtual polarimetry = *physics-constrained estimation of plausible
  polarization-dependent responses*, not measurement. Hatted symbols (Ŝ, DoLP_hat, AoLP_hat) always denote estimates.
* Neither "diffuse = unpolarized" nor "specular = fully polarized" is assumed. Copper/bronze are conductors: dichromatic white-highlight
  separation is not valid, conductor Fresnel (n + ik) is used.
* Recent prior art exists for RGB→polarization estimation (Lin et al., NeurIPS 2025; GenPolar) and for "virtual polarization filtering"
  (IEVPF). See `docs/NOVELTY_ANALYSIS.md` for the refined, defensible claims.

## Quick start
```bash
pip install -r requirements.txt            # torch CPU is enough
export PYTHONPATH=src                      # or: pip install -e .
python -m pytest -q                        # 115+ tests, ~30 s on CPU
python scripts/run_synthetic_validation.py # physics modules vs renderer ground truth (SYNTHETIC)
python scripts/make_figures.py             # figures 1-15 (result-dependent ones skip, no placeholders)
python scripts/make_tables.py              # header-only CSV schemas in tables/
python scripts/train.py --config configs/default.yaml
python scripts/run_ablation.py --config configs/ablation.yaml --arms cumulative
python scripts/benchmark.py --size 128
```

## Colour-space options
CIELAB and HSV are first-class alternatives to RGB (`net.color_spaces: [rgb|lab|hsv ...]`, hue encoded as cos/sin). Study configs:
`configs/color_space_comparison.yaml`; arms generated by `vpc.experiments.ablation.color_space_configs`.

## Safety / legal note
Use spent or inert (dummy) cartridge cases only, handled per local regulations; no live ammunition is needed anywhere in this work.
